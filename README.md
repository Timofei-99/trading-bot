√# trading-bot

Движок исполнения стратегий ICT/SMC. Одна и та же стратегия без изменений работает в трёх режимах — историческом реплее, симуляции на живом фиде и в бирже; меняется только адаптер исполнения.

Документ описывает **механику**, а не кнопки: как принимается решение о филле, что именно гарантировано, где модель расходится с реальностью и какие числа считать достоверными.

```bash
npm install && npm run seed-cache
npm run cli -- --help
```

---

## 1. Три режима и их модели исполнения

Ключ к чтению любого результата — понимать, какая модель филла его породила.

| | Бэктест | Paper | Live (Bybit) |
|---|---|---|---|
| Данные | история | живой фид | живой фид |
| Вход | **филлится на сигнальном баре** | лимитка ждёт возврата цены | лимитка на бирже |
| Выход | движок проверяет бар | движок проверяет бар | **исполняет биржа** |
| Издержки | opt-in, дефолт 0 | дефолт 0.001 | реальные |
| Состояние | в памяти | журнал + restore | журнал + сверка с биржей |

### Бэктест: filled-on-signal

Ордер размещается и `update()` вызывается **на одном и том же баре**. Это не упрощение, а модель отложенной лимитки: история уже показала, что бар коснулся уровня, поэтому филл считается состоявшимся. Отсюда жёсткое требование к `Signal.entry` — он обязан быть уровнем из **прошлых** баров (граница FVG, край ордер-блока, экстремум сессии). Возьмёте `close` текущего бара — получите заглядывание в будущее, и все числа станут фикцией.

Порядок разрешения выхода внутри бара: **TP → SL → expiry**. Когда бар задел оба уровня, внутрибарную последовательность из OHLC восстановить нельзя, и модель разрешает её в пользу цели. Это оптимистично. `--worst-case` инвертирует порядок (SL первым) — используйте для стресс-оценки, дефолт оставлен ради паритета с эталоном.

### Paper: fill-on-touch, строго после сигнального бара

Ордер выставляется **после** закрытия сигнального бара и филлится, только если цена вернётся к уровню на одном из следующих закрытых баров (`low <= entry` для лонга). Условие строгое: `candle.time > order.placedAt`.

**Разница между бэктестом и paper на одних данных — это метрика достижимости ваших входов.** Бэктест даёт 150 сделок, paper за тот же период — 20? Значит бэктест считал исполнимым то, к чему цена не возвращалась. Это единственный способ измерить оптимизм модели filled-on-signal, и ради него paper существует.

Неисполненный вход отменяется по `--entry-timeout` (дефолт 60 мин) — аналог `unfilledtimeout` во freqtrade.

### Live: выходы принадлежат бирже

TP и SL **прикреплены к ордеру входа** и исполняются матчинг-движком Bybit. Процесс может спать, упасть или потерять связь — стоп сработает. `sync()` не решает выходы, а наблюдает их: опрашивает статус ордера и фиксирует то, что уже случилось.

Когда бар задел оба уровня, а открытых ордеров на бирже не осталось, выход атрибутируется **стопу** — консервативное чтение, раз биржа не сообщает, что сработало первым.

## 2. Гарантия отсутствия заглядывания в будущее

Это центральный инвариант, на нём держится осмысленность всех чисел.

**В бэктесте.** На каждом баре `BacktestEngine` строит новый `MarketContext`, куда для **каждого** таймфрейма попадают только бары с `timestamp <= время текущего бара` (через `searchSortedRight` — строгая верхняя граница). Стратегия не может увидеть будущее, потому что оно ей физически не передано. Это свойство закреплено `packages/core/src/engine/lookahead-bias.spec.ts` и трассой видимости в `test/parity/engine-visibility.parity.spec.ts`, сверенной с эталоном бар за баром на годовой истории.

**В живом режиме.** Биржа отдаёт последнюю, ещё формирующуюся свечу как обычный элемент ответа OHLCV — классический источник фантомной доходности у самописных ботов. `LiveEngine` фильтрует каждую серию по `visibleAt(now - timeframeMs)`: бар, открытый в `T` на таймфрейме `D`, становится видим только при `T + D <= now`. Формирующаяся свеча к стратегии не попадает никогда.

Проверить вживую:

```bash
npm run cli -- paper --once
# warmup 15m: 500 closed bars, last 2026-07-27T12:45:00.000Z   ← при 13:12 UTC
```

**Чего гарантия не покрывает:** HTF-бар с меткой открытия становится видимым в момент своего открытия. Бар 4h с меткой 12:00 виден на 15m-баре 12:00, хотя содержит данные до 15:59. Это унаследованная семантика меток; учитывайте при работе с HTF-контекстом.

## 3. Модель издержек

Считается на закрытии сделки, комиссия берётся с обеих сторон.

```
pnlPct  = gross − feeRate × (1 + exitPrice / entryPrice)
balance −= positionSize × (entryPrice + exitPrice) × feeRate
```

Комиссия выражена относительно входного номинала, чтобы процент оставался сопоставим с валовым. Направление роли не играет — оба конца круга платятся всегда.

**Проскальзывание применяется только к маркет-подобным выходам** — стоп и экспирация. Вход и тейк — лимитные, они исполняются по своей цене или лучше:

```
SL/expiry:  price × (1 ∓ slippage)     лонг / шорт
TP/entry:   без изменений
```

Порядок суммирования в отчёте и в кластеризации SNR — наивный, слева направо. Это не небрежность: так считал Python 3.11, и компенсированное суммирование сломало бы паритет.

### Насколько это меняет картину

```bash
npm run cli -- backtest:ob4h                                          # PF 0.99  PnL  −0.62%
npm run cli -- backtest:ob4h --fee 0.001                              # PF 0.47  PnL −30.62%
npm run cli -- backtest:ob4h --fee 0.001 --slippage 0.0005 --worst-case # PF 0.43  PnL −35.55%
```

Год BTC, 150 сделок. Одна комиссия 0.1% переводит 18 прибыльных сделок в убыточные. **Прогон без `--fee` имеет ровно одно назначение — сверка с эталоном.** Любое торговое решение принимается по прогону с издержками.

## 4. Сайзинг и биржевые ограничения

```
risked     = balance × riskPerTrade / |entry − stopLoss|
affordable = balance / (entry × (1 + feeRate))        ← спот: нельзя купить больше, чем есть
size       = min(risked, affordable)
```

Дальше в live добавляются три отсечки:

1. `amountToPrecision` / `priceToPrecision` — округление к шагу инструмента;
2. `market.limits.amount.min` — минимальный объём;
3. `market.limits.cost.min` — минимальный номинал.

Нарушение любой — отказ **до** отправки ордера, с внятным текстом. Узкий стоп при малом депозите упрётся в `affordable` или в минимумы биржи; это ожидаемо, а не баг.

Шорт на споте отклоняется явно (`Spot trading supports long entries only`), а не превращается молча в продажу. Для шортов нужен `BYBIT_CATEGORY=linear` — категория параметризована, но перпетуалы не проверены (см. §11).

## 5. Контракт стратегии

```ts
class MyStrategy extends Strategy {
  readonly name = 'my_strategy';
  readonly version = '1.0';

  checkEntry(context: MarketContext): Signal | null { … }
  checkExit?(context: MarketContext, trade: Trade): boolean;   // вызывается только в live
}
```

Регистрация — одна запись в `BUILT_IN_STRATEGIES` (`packages/app/src/strategy-registry.service.ts`): `id`, `version`, `requiredTimeframes`, `defaultParams`, `create`. После неё стратегия адресуема по строковому id в CLI, paper, live и REST.

### Семантика Signal

| Поле | Требование |
|---|---|
| `entry` | уровень из прошлых баров. Не из OHLC текущего бара |
| `stopLoss` / `takeProfit` | то же; в live уходят на биржу как прикреплённые ордера |
| `timestamp` | **обязан** равняться времени последнего видимого бара: `candles.lastTime` |
| `expiryTime` | опционально; выход по рынку при `candleTime >= expiryTime` |
| `meta` | произвольные факты для отчётов и разбора |

### Состояние

Движок отдаёт новый `MarketContext` на каждом баре, но **тот же объект стратегии**. Состояние между барами хранится в полях — так работают `frankfurt-ib-50` (состояние сессии по локальной дате) и `h1-3m-classic` (состояние по UTC-дню). В бэктесте это безопасно: прогон однопоточный и последовательный.

### Детекторы: контракт и meta-ключи

Все девять — `detect(candles: CandleSeries) → Pattern[]`, без состояния: параметры в конструктор, `detect` — чистая функция от переданных баров. Типизированные факты лежат в `pattern.meta`:

| Детектор | Ключи `meta` |
|---|---|
| `FvgDetector` | `direction`, `mitigated`, `impulse_time`, `gap_size` |
| `OrderBlockDetector` | `direction`, `mitigated`, `swing_time` |
| `LiquidityDetector` | `side` (`buy`/`sell`), `swept` |
| `StructureDetector` | `direction`, `broken_level` |
| `PremiumDiscountDetector` | `zone` (`premium`/`discount`), `direction`, `range_high`, `range_low`, `equilibrium` |
| `SnrDetector` | `side` (`support`/`resistance`), `touches`, `broken` |
| `FractalDetector` | `fractal_type`, `level` |
| `KillzoneDetector` | `name`, `candle_count` |
| `InitialBalanceDetector` | `session`, `session_date`, `mid`, `duration_minutes` |

Времена в `meta` — epoch ms, даты сессий — строки `YYYY-MM-DD`. `Pattern.endTime === null` означает «ещё активен» (немитигирован, не снят, не пробит).

**Двухфазная митигация ордер-блока:** цена должна сначала **закрыться** за зоной, и только потом возврат в неё считается митигацией. Без первой фазы свеча выхода митигировала бы блок, который сама и создала. У FVG митигация однофазная — гэп по определению уже покинут ценой.

**Свинги строгие:** равный сосед дисквалифицирует экстремум. Бары ближе `swingLength` к краю серии пивотами быть не могут — это же свойство защищает детекторы от заглядывания вперёд на скользящем окне.

## 6. Бэктест: как запускать

### 6.1. Основная команда

```bash
npm run cli -- backtest --strategy <id> --fee 0.001 [опции]
```

Работает с **любой** зарегистрированной стратегией, включая вашу. Таймфреймы и символ берутся из реестра, поэтому минимальный вызов — только id и комиссия:

```bash
npm run cli -- backtest --strategy my_strategy --fee 0.001
```

Без `--strategy` команда печатает список доступных id. Без `--fee` печатает предупреждение, что результат валовый и торговать по нему нельзя.

| Опция | Дефолт | Назначение |
|---|---|---|
| `--strategy <id>` | — | обязательна; см. `npm run cli -- strategies` |
| `--params <json>` | из реестра | перекрывает только названные поля |
| `--source <name>` | `binance` | `binance` \| `yahoo` \| `mt5` |
| `--symbol <sym>` | из стратегии, иначе `BTC/USDT` | инструмент |
| `--timeframes <list>` | из стратегии | через запятую: `4h,15m` |
| `--base <tf>` | самый мелкий | таймфрейм, по которому идёт цикл |
| `--start` / `--end` | `2023-01-01` / `2024-01-01` | период |
| `--window <bars>` | `500` | сколько баров видит стратегия |
| `--balance <usd>` | `10000` | стартовый депозит |
| `--risk <доля>` | `0.01` | риск на сделку |
| `--fee <доля>` | `0` | комиссия с каждой стороны |
| `--slippage <доля>` | `0` | проскальзывание на стопах и экспирации |
| `--worst-case` | выкл | бар задел оба уровня → считать стопом |
| `--max-daily-dd <доля>` | выкл | пауза на день после такого убытка |
| `--trades` | выкл | печатать каждую сделку, не только итог |
| `--csv` / `--tz` | — | для `--source mt5` |

Пресеты `backtest:ob4h`, `backtest:h1-3m`, `backtest:frankfurt` — то же самое с зашитыми параметрами встроенных стратегий; для своей используйте `backtest`.

### 6.2. Откуда берутся данные и куда ложатся

| `--source` | Откуда | Куда кэшируется | Что нужно |
|---|---|---|---|
| `binance` | ccxt, публичный API | `data/cache/binance_<SYM>_<tf>.ndjson` | интернет при промахе кэша |
| `yahoo` | yahoo-finance2 | не кэшируется | интернет; ≤60 дней для 5m, ≤730 для 1h |
| `mt5` | ваш CSV-файл | не кэшируется | файл на диске |

**Кэш заполняется сам.** Первый запрос диапазона идёт в сеть, результат ложится в `data/cache/`, повторные прогоны офлайн и мгновенны. Догружается только недостающее: если в кэше есть январь–июнь, а вы просите январь–декабрь, скачается июль–декабрь.

`npm run seed-cache` заполняет кэш годом BTC/USDT (4h + 15m) из фикстур репозитория — чтобы первый бэктест работал сразу и без сети.

**Файлы MT5 кладите в `data/`** (каталог в `.gitignore`, кроме кэша ничего не мешает):

```bash
# экспорт из MT5: правый клик по графику → Save As → CSV
cp ~/Downloads/DAX_M1.csv data/dax_1m.csv
npm run cli -- backtest --strategy frankfurt_ib_50 --csv data/dax_1m.csv --tz Europe/Berlin --fee 0.0005
```

`--tz` — часовой пояс **сервера брокера**, не ваш. Ошибка здесь сдвинет все сессии.

### 6.3. Форматы дат

`2023-06-01` — UTC-полночь. Полный ISO обязан нести зону: `2023-06-01T00:00:00Z`.

Значение без зоны **отвергается** — `Date.parse` прочитал бы его в локальной зоне машины и молча сдвинул период на ваш офсет. Календарно невозможные даты (`2023-02-30`, `2023-02-29`) тоже отвергаются: `Date.parse` переехал бы на 2 марта без единого слова.

### 6.4. Как читать вывод

```
strategy : OB_4h_FVG_15m v1.0
data     : binance BTC/USDT [4h, 15m], base 15m
costs    : fee 0.001 per side, slippage 0
  4h: 2191 bars  (2023-01-01 – 2024-01-01)      ← сколько истории реально загрузилось
  15m: 35036 bars  (2023-01-01 – 2024-01-01)

=== Backtest Report ===
  Total trades    : 150
  Winners / Losers: 59 / 91
  Win rate        : 39.3%
  Profit factor   : 0.47      ← валовая прибыль / валовый убыток; < 1 = убыточно
  Total PnL       : -30.62%   ← сумма процентов сделок, не сложный процент
  Max drawdown    : 38.40%    ← глубочайшая просадка кривой суммы процентов
```

`Total PnL` — арифметическая сумма процентных результатов, а не рост депозита. Просадка считается по той же кривой.

Мало сделок или ноль? Проверьте строку `bars`: пустой или короткий диапазон означает промах кэша без сети. Бары есть, а сделок нет — не сработали условия стратегии.

**`--trades` показывает каждую сделку** — читайте её, а не только итог: там видно, стоят ли входы на уровнях, к которым цена реально возвращается.

```
    1  2023-06-06T10:45:00.000Z  long  @ 25750     → sl  @ 25629.99   -0.67%
    2  2023-06-08T08:00:00.000Z  long  @ 26414.15  → tp  @ 26531.05    0.24%
```

### 6.6. Скелет своей стратегии

`packages/core/src/strategies/my.strategy.ts`:

```ts
import { FvgDetector } from '../detectors/fvg.detector';
import { MarketContext } from '../domain/market-context';
import { Strategy } from '../domain/ports';
import { Direction, Signal } from '../domain/signal';

export class MyStrategy extends Strategy {
  readonly name = 'my_strategy';
  readonly version = '1.0';
  readonly minRr: number;

  constructor(options: { minRr?: number } = {}) {
    super();
    this.minRr = options.minRr ?? 2;
  }

  checkEntry(context: MarketContext): Signal | null {
    const candles = context.candles('15m');
    if (candles.isEmpty) {
      return null;
    }

    const gaps = new FvgDetector({ timeframe: '15m' }).detect(candles);
    const fresh = gaps.filter((g) => g.meta.direction === 'bullish' && !g.meta.mitigated);
    if (fresh.length === 0) {
      return null;
    }

    const gap = fresh[fresh.length - 1];
    const entry = gap.high;          // уровень из ПРОШЛЫХ баров — см. §1 и §5
    const stopLoss = gap.low;

    return new Signal({
      symbol: context.symbol,
      direction: Direction.Long,
      entry,
      stopLoss,
      takeProfit: entry + (entry - stopLoss) * this.minRr,
      timeframe: '15m',
      timestamp: candles.lastTime as number,   // обязательно последний видимый бар
      strategyName: this.name,
      strategyVersion: this.version,
    });
  }
}
```

Регистрация — одна запись в `BUILT_IN_STRATEGIES` (`packages/app/src/strategy-registry.service.ts`):

```ts
{
  id: 'my_strategy',
  version: '1.0',
  description: 'Ретест бычьего FVG на 15m',
  requiredTimeframes: ['15m'],
  defaultParams: { minRr: 2 },
  create: (params) => new MyStrategy(params),
},
```

Проверка и запуск:

```bash
npm run cli -- strategies                                             # id появился?
npm run cli -- backtest --strategy my_strategy --fee 0.001 --trades
npm run cli -- paper --strategy my_strategy --params '{"minRr":3}' --once
```

## 7. Остальные команды

### Paper

```bash
npm run cli -- paper --strategy my_strategy [--params '{"minRr":3}'] [--symbol BTC/USDT]
                     [--exchange bybit] [--balance 10000] [--risk 0.01] [--fee 0.001]
                     [--slippage 0] [--worst-case] [--entry-timeout 60]
                     [--max-daily-dd 0.03] [--max-losses 4] [--journal <path>] [--once]
```

`--once` — прогреть контекст, обработать один тик, напечатать состояние, выйти. Годится для smoke и для cron.

### Live

```bash
export BYBIT_API_KEY=… BYBIT_API_SECRET=…      # testnet.bybit.com — отдельный аккаунт
npm run cli -- trade --symbol BTC/USDT --max-daily-dd 0.03 --max-losses 4
```

Переменные: `BYBIT_API_KEY`, `BYBIT_API_SECRET` (обязательны), `BYBIT_CATEGORY` (`spot`|`linear`, дефолт `spot`), `BYBIT_LIVE` (см. ниже). Ключ — с торговлей и **без права вывода**, желательно с IP-allowlist. Секрет не логируется; в вывод идёт маскированный префикс.

**Тестнет — дефолт.** Реальные деньги требуют двух независимых сигналов: `BYBIT_LIVE=true` в окружении **и** `--live` в команде. Любой поодиночке — отказ по имени недостающего. Плюс ручное подтверждение вводом символа (`--yes` пропускает).

### Останов

```bash
npm run cli -- halt   --journal data/journal/<file>.ndjson --reason "…"
npm run cli -- resume --journal data/journal/<file>.ndjson
```

Пишет в журнал, а не сигналит процессу: работает, когда бот не запущен, и **переживает рестарт**. Вступает в силу на следующем тике.

### Прочее

```bash
npm run cli -- strategies                                  # реестр с параметрами
npm run cli -- visualize --chart-month 2023-02 --top 3     # HTML в reports/
npm run start                                              # REST на 127.0.0.1:3000
npm run verify                                             # format, lint, typecheck, test
npx jest test/parity                                       # паритет с Python-эталоном
```

## 8. Живой цикл: что происходит на старте и на каждом баре

**Старт (`BybitAdapter.start`)**

1. Сверка часов с биржей; расхождение > 3 с — отказ. Bybit отклоняет подписанный запрос вне `recv_window`, и без этой проверки вы получили бы серию невнятных 401.
2. Загрузка правил рынка: `priceTick`, `amountStep`, минимумы.
3. Проигрывание журнала.
4. **Сверка с биржей.** Если журнал считает ордер висящим — спросить биржу, что с ним стало. Пока процесс лежал, он мог исполниться.

**Каждое закрытие базового таймфрейма**

```
refresh (только закрытые бары) → срез контекста по текущему бару
  → sync():  филл / отмена / таймаут входа, затем наблюдение выхода
  → kill switch: оценить дневной результат, при пробое — halt + отмена висящих
  → есть позиция? → checkExit()
  → нет позиции и не halt и нет висящего ордера? → checkEntry()
  → сон до следующего закрытия + graceMs (3 с)
```

Исключение внутри тика логируется и не убивает цикл — следующая свеча повторит попытку.

**Идемпотентность.** У каждого ордера `orderLinkId` = наш собственный id. Повтор после потерянного ответа биржа отклонит, а не откроет вторую позицию. Ретраи — экспоненциальный backoff, 3 попытки, только на безопасных к повтору вызовах.

**Журнал.** `entry_placed` пишется **до** вызова API, `entry_acknowledged` — **после**. Разрыв между ними и есть состояние «мы не знаем, дошло ли»; именно его разбирает сверка при следующем старте. Без второго события рестарт терял позицию, исполнившуюся во время падения процесса.

## 9. Kill switch

`RiskManager` отвечает на вопрос «приемлем ли этот сигнал» и на следующем баре пробует снова. `KillSwitch` отвечает «должен ли бот вообще торговать» — и, сработав, **остаётся включённым после рестарта**, потому что halt пишется в журнал и проигрывается при старте. Лимит убытка, сбрасываемый перезапуском, — не лимит убытка.

| Триггер | Окно |
|---|---|
| `--max-daily-dd <доля>` | реализованный убыток за **UTC-день** |
| `--max-losses <n>` | убыточные подряд, **сквозь дни** |

При срабатывании: висящие ордера отменяются, **открытая позиция не трогается** — её стоп уже на бирже, а продажа по рынку зафиксировала бы убыток, которого стоп мог и не взять. Закрытие позиции — ручное решение. Снятие — только `resume`.

## 10. Артефакты и форматы

```
data/cache/<source>_<symbol>_<tf>.ndjson    свечи: [time,o,h,l,c,v] построчно
data/journal/<mode>_<strategy>_<sym>.ndjson события ордеров и сделок
data/journal/<…>.log.ndjson                 каждый вызов биржи и ответ (live)
reports/*.html                              графики Plotly (CDN, без зависимости)
test/fixtures/golden/                       эталоны паритета — в git, это важно
```

Типы событий журнала: `session`, `entry_placed`, `entry_acknowledged`, `entry_settled`, `position_closed`, `halted`, `resumed`. Запись синхронная — попадает в файл до возврата из метода, поэтому крах теряет максимум строку в процессе записи (оборванная последняя строка при чтении отбрасывается с предупреждением; битая строка в середине — ошибка).

Нефинитные значения отвергаются и в кэше, и в журнале: `JSON.stringify(NaN)` даёт `null`, который читается обратно нулём, а нулевая цена проходит сквозь любой стоп.

Логи биржи редактируют всё, чей ключ похож на секрет, на любой глубине — намеренно не по списку путей, потому что утечёт ровно то поле, которое в список не внесли.

## 11. Что не моделируется

Читайте как список причин, по которым live разойдётся с бэктестом.

- **Частичные исполнения.** Ордер либо исполнен целиком, либо нет.
- **Стакан и глубина.** Проскальзывание — константа из флага, не функция размера.
- **Комиссия мейкера.** Одна ставка на обе стороны; лимитный вход на самом деле дешевле.
- **Funding для перпетуалов.** Категория `linear` параметризована, но фандинг не считается — на перпетуалах результат бэктеста будет завышен.
- **Несколько позиций и символов.** Одна позиция на символ, один символ на процесс.
- **WebSocket.** Поллинг REST по закрытию свечи. Для 15m это адекватно, для скальпинга — нет.
- **Проскальзывание входа.** Лимитка филлится строго по своей цене.
- **HTF-бар виден по метке открытия** (см. §2).
- **Киллзона через полночь** группируется по UTC-суткам: полоса 22:00–02:00 соберёт часы 0, 1, 22, 23 **одних и тех же** суток, а не непрерывный отрезок. Унаследовано и закреплено фикстурой.
- **REST API без аутентификации** — слушает только loopback, наружу не выставлять.

## 12. Паритет и регрессии

`test/fixtures/golden/` — поведение предыдущей реализации, замороженное как данные: свечи, выходы всех девяти детекторов в 28 конфигурациях, три полных прогона движка, трасса видимости, DST-края MT5-загрузчика.

Сверка **точная**: `toEqual` сравнивает числа через `Object.is`, без epsilon. Python float, numpy float64 и JS number — все IEEE-754 double, поэтому одинаковые операции в одинаковом порядке дают одинаковые биты.

**Фикстура — спецификация.** Упал паритетный тест — вы изменили поведение; правьте код, а не эталон. Практическое следствие: любая новая опция обязана иметь дефолт, равный прежнему поведению, и это свойство само проверяется тестом «дефолты === явные нули».

Быстрая проверка после правки:

```bash
npx jest test/parity && npx jest -t "look-ahead"
```

## 13. Диагностика

| Сообщение | Причина |
|---|---|
| `Local clock is … ms from Bybit` | системное время разошлось; подписанные запросы всё равно бы падали |
| `Refusing to trade real funds without both` | нужны `BYBIT_LIVE=true` **и** `--live` |
| `--start: … has no timezone` | добавьте `Z` или используйте голую дату |
| `… is not a real date` | календарно невозможная дата |
| `below the venue minimum` | размер или номинал ниже минимума инструмента |
| `Position size … balance too small` | `affordable` схлопнулся: стоп слишком узкий для депозита |
| `Already engaged on <symbol>` | одна позиция на символ |
| `Spot trading supports long entries only` | шорт на споте; нужен `linear` |
| Бот не входит | проверьте журнал на `halted`; снимается `resume` |
| Паритет упал после правки | правьте код, не фикстуру |
